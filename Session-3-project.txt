Frontend Practical Assignment
React Task Manager
Scenario
You are working as a Frontend Developer for a productivity platform called TaskFlow.
Your task is to build a responsive Task Manager application using React and TypeScript.
The application should allow users to view, add, complete, and delete tasks while
demonstrating proper React component structure, props, state management, events, and
useEffect.
The goal is not only to make the application work, but to build it using React thinking and
reusable components.
Requirements
1. Application Header
Create a header containing:
● Application name: TaskFlow
● Short description such as:
Organize your tasks. Stay productive.
The header should be implemented as a separate React component.
2. Task Summary
Create a summary section showing:
● Total tasks
● Completed tasks
● Remaining tasks
Example:
Total: 8
Completed: 3
Remaining: 5
The values must update automatically when the task state changes.
3. Add Task
Create a form that allows the user to add a new task.
The form should contain:
● Task title input
● Add Task button
Requirements:
● The task title cannot be empty.
● When the user adds a task, the UI should update immediately.
● The new task should be added to the existing tasks state.
● Do not directly modify the existing state array.
4. Task List
Display the tasks inside a reusable task list.
Each task should display:
● Task title
● Completed / Pending status
● Toggle completion control
● Delete button
Example:
☐ Learn React Props Pending Delete
☑ Practice useState Completed Delete
☐ Build Task Manager Pending Delete
The task list should be generated dynamically from the tasks state.
Do not manually create a component for every task.
5. Complete / Uncomplete Task
The user must be able to change a task between:
Pending ↔ Completed
When the status changes:
● Update the React state.
● Update the UI automatically.
● Update the task summary.
Do not manipulate the DOM manually.
6. Delete Task
Each task should contain a Delete button.
When clicked:
● Remove the correct task from the state.
● Update the task list.
● Update the task summary.
The original state array should not be directly mutated.
7. Task Filters
Create three filters:
All | Pending | Completed
All
Display all tasks.
Pending
Display only tasks that are not completed.
Completed
Display only completed tasks.
Filtering should be derived from the current application state.
8. Empty State
Display a clear message when there are no tasks to display.
Example:
No tasks found.
The message should also work correctly when a filter has no matching tasks.
For example, if there are no completed tasks:
No completed tasks yet.
9. Initial Data
When the application starts, load an initial list of tasks from an API.
Use:
https://dummyjson.com/todos
Use useEffect to perform the initial data loading.
The fetched data should then be stored inside React state and displayed using your
React components.
10. Loading & Error States
While the initial tasks are being loaded, display a loading state.
Example:
Loading tasks...
If loading fails, display a clear error message.
Example:
Something went wrong while loading tasks.
The application should not crash if the API request fails.

React components.
Your structure may include components such as:

TypeScript Requirements
The project must use React with TypeScript.
Create appropriate types/interfaces for your data.
For example:
interface Task {
id: number;
todo: string;
completed: boolean;
}
Use typed:
● Props
● State
● Functions
● Event handlers
● API data where appropriate
Avoid using any unless you can explain why it is necessary.
State Requirements
Use React state to manage application behavior.
Your state may include:
tasks
filter
loading
error
Use useState where appropriate.
State updates should be immutable.
For arrays, use approaches such as:
map()
filter()
spread operator
instead of directly modifying the existing array.
useEffect Requirements
Use useEffect for the initial API request.
The application should:
Component renders
↓
useEffect runs
↓
Fetch tasks
↓
Update state
↓
UI re-renders
Use the dependency array correctly based on the required behavior.

AI Usage Requirements
AI must be used as an engineering assistant, not as a replacement for your work.
You must use AI during at least three stages.
Task 1 — Component Planning
Before implementation, provide AI with the project requirements or UI design.
Ask:
Analyze this Task Manager interface and suggest a React component
hierarchy. Explain each component's responsibility, parent-child
relationships, reusable elements, and required props. Do not write the
implementation code.
Review the proposed structure yourself.
You may accept, reject, or modify AI suggestions.
This mirrors the component-analysis approach used in the Session 3 hands-on.
Task 2 — Implementation Review
After implementing the main functionality, ask AI to review your React code for:
● Component responsibilities
● Props usage
● State location
● State mutations
● Repeated code
● TypeScript typing
● useEffect
● List keys
● Unnecessary re-renders
● Maintainability
Ask AI:
Identify the problems and explain why they are problems. Do not rewrite the
entire application.
Task 3 — Testing & Debugging
Test the application yourself and also use AI to help review the behavior.
Test:
● Adding tasks
● Empty task validation
● Completing tasks
● Returning completed tasks to pending
● Deleting tasks
● Filters
● Summary values
● API loading
● Loading state
● Error state
● Responsive behavior
When a problem is found, provide AI with:
● Relevant code
● Expected behavior
● Actual behavior
● Error message if available
Ask AI to explain the likely root cause before suggesting a solution.
This follows the Session 3 workflow of using AI for testing while still manually testing
and reviewing the generated code.
